# Remaining local verification — Windows PowerShell

This updated last-pass handoff is **not** production certified. Do not push it as a completed product until the mandatory failures are fixed and the live verification results are attached to `FINAL_VALIDATION_REPORT.md`.

## Prerequisites

Install Python 3.12, Node.js 22 + npm 10, Docker Desktop (running Linux containers), and Ollama with `qwen2.5-coder:7b` and `nomic-embed-text` if you intend to evaluate real model generation. PostgreSQL 16 is provided by Docker Compose for integration; a **separate `_test` database** is mandatory for tests. None of these model weights is bundled.

Extract the ZIP and open PowerShell inside the `patchproof` repository root. Do not commit `.env` or any real credentials.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
Copy-Item .env.example .env
# Edit .env to set a strong API key and database password.
```

### First: frontend lockfile and compilation

```powershell
.\scripts\bootstrap_frontend.ps1
```

### Trusted Docker sandbox (includes pytest)

```powershell
docker info
.\scripts\test_sandbox.ps1
```

The script builds the pinned trusted `patchproof-pytest:3.12-9.0.2` image at build time, then runs Docker smoke checks and actual integration tests. Docker runs must have network disabled, a non-root UID, bounded memory/CPU/processes and cleanup. Tests requiring uninstalled third-party repository dependencies should **fail or remain unverified**, never be counted as passing. The public API has no Docker socket.

### PostgreSQL integration (dedicated database only)

Configure `PATCHPROOF_DB_PASSWORD` in `.env`, then:

```powershell
docker compose up -d db
# Create a separate database named patchproof_test using the operator's DB credentials.
# If it already exists, do not recreate or delete it.
docker compose exec -T db createdb -U patchproof patchproof_test
# In this terminal only, point both migration and integration test URLs to
# the dedicated patchproof_test database, never to your application DB.
$env:PATCHPROOF_TEST_DATABASE_URL = 'postgresql+psycopg://patchproof:<DB_PASSWORD>@127.0.0.1:5432/patchproof_test'
$env:PATCHPROOF_DATABASE_URL = $env:PATCHPROOF_TEST_DATABASE_URL
$env:PATCHPROOF_REQUIRE_POSTGRES = '1'
.\.venv\Scripts\python.exe -m alembic upgrade head
.\.venv\Scripts\python.exe -m pytest -q tests/test_postgres_integration.py tests/test_postgres_concurrency.py -rs
Remove-Item Env:PATCHPROOF_DATABASE_URL
Remove-Item Env:PATCHPROOF_TEST_DATABASE_URL
Remove-Item Env:PATCHPROOF_REQUIRE_POSTGRES
```

Replace `<DB_PASSWORD>` with your *test-service* password, correctly URL-encoded. The integration scripts reject names not ending `_test`. **Do not** use a production host or URL. The integration tests clean up only records they created; they do not drop the database.

## Last source-pass additions

The deterministic Playwright fixture `apps/web/e2e/fixtures/calculator.zip` is now included. Playwright will **not** reuse existing API/Vite servers, to avoid running its tests against an existing application database. Stop existing servers on ports 8000/5173 before the browser suite. In Windows PowerShell, use `npm.cmd` or `scripts/bootstrap_frontend.ps1` to avoid script execution-policy issues; the bootstrap generates a genuine lockfile when registry access works. `scripts/verify.ps1` and `.sh` clear inherited PostgreSQL test environment settings before running their fixture suites and migrate only a newly created SQLite database. Real PostgreSQL tests must be run separately with the explicit dedicated `_test` URL described above.

The final handoff still has no npm lockfile. This is a **source/dependency release blocker**, not just a local runtime verification checkbox. Remaining npm failures may expose actual frontend code issues; return those logs for correction rather than publishing as a completed product.
